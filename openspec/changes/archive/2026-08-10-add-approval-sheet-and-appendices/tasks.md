## 2. Appendix and annex structure

- [x] 2.1 Verify what `\backmatter` does to the chapter counter in this template as it stands, by compiling. The inherited `\backmatter` sets `\@mainmatterfalse`, which makes `\chapter` unnumbered — confirm this against the actual build before designing around it, since `\frontmatter`/`\mainmatter` are already redefined here (`UnifeiICTReport.sty:997–1012`) and the interaction is not obvious from reading. Confirmed by reading book.cls's kernel source directly and this .sty's actual `\frontmatter`/`\mainmatter` code: `\backmatter` is not redefined here, and the inherited one only unnumbers plain `\chapter` (irrelevant — appendices use a dedicated counter, not `\chapter`) and leaves `\pagestyle` at "plain" (page numbers stay visible and continuous). `\backmatter` does not need redefining.
- [x] 2.2 Provide commands opening the appendix group and the annex group, each with an independent capital-letter sequence. `\apendices`/`\anexos` (group) and `\apendice{label}{title}`/`\anexo{label}{title}` (entries), each pair backed by its own `\newcounter`.
- [x] 2.3 Provide a heading style: word + letter + travessão + title, centered, carrying the same emphasis as the primary section (`\unifeifont`, `unifeiblue`, `\Large\bfseries`, uppercase — see `UnifeiICTReport.sty:883`), with no numeric indicative. Confirmed visually on rendered pages 29/30.
- [x] 2.4 Handle letters past Z per §4.2.3.3 (`AA`, `BB`, …), or fail with an explicit message naming the limit. `\Alph` overflows with a raw LaTeX error past 26, so doing nothing means a hard failure in exactly the case the norm names. Implemented via `\@Alph{<number>}` (not `\Alph{<counter>}`/`\setcounter`, which are not expandable and would corrupt `\refstepcounter`'s internal `\edef` — caught and fixed during a dedicated spike). Doubles past 26 (AA…ZZ). Verified standalone: 1→A, 27→AA, 52→ZZ, all fully expandable inside an `\edef`.
  - **Correção pós-verificação (auditoria).** A redação anterior desta tarefa afirmava que o caso >52 "raises a `\PackageError` naming the 52-entry ceiling" — meia verdade: eu tinha testado 1, 27 e 52, nunca 53. Testado agora, o erro disparava, mas `\PackageError` não é expansível e estava dentro de `\the<contador>`, expandido pelo `\protected@edef` do `\refstepcounter`: o `\GenericError` inteiro era gravado no `.aux` como o *valor* do rótulo (`\newlabel{...}{{\GenericError ...}}`), corrompendo o rótulo e re-disparando o erro a cada compilação seguinte, além de sair em caixa alta engolido pelo `\MakeUppercase` do título. É exatamente a classe de bug que a própria tarefa citava para `\setcounter`. Corrigido separando as duas responsabilidades: `\Unifei@GroupLetter` continua puramente expansível (acima de 52 devolve o número cru, só para manter a expansão legal) e o teto passou a ser aplicado por `\Unifei@ChecarTetoGrupo`, chamado logo depois do `\refstepcounter`, em contexto normal. Reverificado com 53 entradas.
- [x] 2.5 Confirm pagination continues the main text without restarting or changing style (§5.3). Confirmed: pages 29/30 continue arabic numbering unbroken from page 28 (end of references).
- [x] 2.6 Add collective `APÊNDICES` and `ANEXOS` entries to the sumário, without section numbers, matching the UFV published model. ## 3. Approval sheet metadata

- [x] 3.1 Design the public interface for examining board members: each needs name, titulação and institution, which does not fit the flat `\supervisor{...}` pattern used today. Whatever is chosen is what authors write against, so settle it before implementing the layouts. Chose a repeatable `\bancamembro{nome}{titulação}{instituição}` that accumulates into a list (via the LaTeX2e kernel's `\g@addto@macro`, no new dependency), replayed in full when the sheet renders — not a key-value package, not a fixed-arity command.
- [x] 3.2 Add metadata for the approval date, the natureza text, and the type-specific extras — company supervisor for the internship type, and the grade field if question 2 in design.md's Open Questions is answered yes. Implemented `\aprovacaodata`, `\notaaprovacao` (both optional — omitting them omits the line entirely, not a blank field) and `\empresasupervisor`. The grade-field open question: answered "yes, but optional" — `\notaaprovacao` exists and is used when declared, never required.
- [x] 3.3 Reuse existing declarations (`\title`, `\subtitle`, `\author`, `\supervisor`, `\subject`) rather than requiring them to be restated. Confirmed in all four layouts — none redeclare these.

## 4. Approval sheet command

- [x] 4.1 Implement the command with a type parameter defaulting to the course-report type, and an explicit error listing the supported types when an unknown one is given. `\folhaaprovacao[<tipo>]`, `O{disciplina}` default. Verified the error path directly: an invalid type produces `Package UnifeiICTReport Error: Tipo de folha de aprovação desconhecido: '<tipo>'` naming the four supported values, not a silent fallback.
- [x] 4.2 Implement the four layouts: course report, internship report, undergraduate final project, master's dissertation. All four implemented and each individually compiled and rendered for visual verification (disciplina, estagio, tcc — dissertacao shares tcc's code path, differing only in natureza wording).
- [x] 4.3 Set the natureza in single spacing, aligned from the middle of the text block to the right margin (§5.2). Note this is the same rule the title page already follows — check whether `\maketitle` already implements it and reuse rather than duplicate. Confirmed `\maketitle` already does exactly this (`\hfill` + `parbox{0.5\textwidth}` + `\setstretch{1.0}`, ~line 946) and reused the identical pattern via `\Unifei@FolhaAprovacaoNatureza`, rather than re-deriving it.
- [x] 4.4 Emit no heading, no section number and no sumário entry (§5.2.4). Satisfied by construction — the sheet never calls `\chapter`/`\section`/`\addcontentsline`.
- [x] 4.5 Render correctly-shaped blank signature blocks when board members have not been declared. This is the normal case, not an error — the sheet is printed to be signed (§4.2.1.3). Do not warn. Caught a real bug here during verification: the first implementation used `\ifblank{#1}` directly on arguments that were sometimes macro *references* (`\@supervisor`) rather than literal text — a macro reference is always one token, never blank, even when the referenced macro is empty, so an undeclared supervisor would have rendered a stray empty bold line instead of correctly omitting it. Fixed by normalizing both cases through `\edef` and testing with `\ifdefempty`. Verified with a genuinely blank `\bancamembro{}{}{}`: renders just the signature rule, nothing below it.
- [x] 4.6 Comment in the `.sty` which types are norm-contemplated and which are institutional adaptation: the course report is covered by §1 Escopo and §4.2.1.1.1(e), the internship report only by "e similares". This prevents a future editor from "correcting" the course-report layout on the false belief that it is unregulated. Done in the section header comment above the approval-sheet code.
- [x] 4.7 Subordinate the subtitle to the title with a colon, per §4.1.1 alínea d). Added after the main implementation, when the rule was checked directly against the norm PDF in `.refs/` (its body text does not extract — the pages had to be rendered and read). All three title-bearing pages were non-conformant: capa, folha de rosto and this sheet printed title and subtitle with no mark of subordination. Implemented as the `\title`/`\subtitle`/`\fulltitle` trio: `\subtitle` takes only the subtitle text and the template supplies the colon, so no document can have a subtitle without the mark, nor a doubled colon from an author who typed one. `\fulltitle` is the composed form (title + colon + subtitle), written to be fully expandable so it survives `\edef`, PDF metadata and cross-references — verified by landing it in `pdftitle`. A shared block macro renders all three pages, parameterized only by letter case: upper on capa and folha de rosto, normal here. Title and subtitle now form one continuous block, distinguished by weight (bold title, non-bold subtitle) rather than by size or a paragraph break. Verified in both directions on all three pages: with a subtitle the block renders correctly; without one, no orphan colon appears anywhere.
