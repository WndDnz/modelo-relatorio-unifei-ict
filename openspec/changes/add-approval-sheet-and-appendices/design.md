## Context

See proposal.md — Why. Two normative sources were read directly: ABNT NBR 14724:2024 (§1, §3.3, §3.4, §4.2.1.1.1, §4.2.1.3, §4.2.3.3, §4.2.3.4, §5.2, §5.2.3, §5.2.4, §5.3) and the UFV 2025 normalization guide, which supplies rendered layout models the norm itself does not.

The existing structural machinery this change has to work with or around:

- `UnifeiICTReport.sty:997–1012` — `\frontmatter` and `\mainmatter` are redefined. `\frontmatter` sets arabic numbering from the start and hides page numbers; `\mainmatter` deliberately does *not* reset the counter, so numbering is continuous across the whole document. `\backmatter` is **not** redefined; the inherited one from `book` only does `\@mainmatterfalse`, which makes `\chapter` unnumbered.
- `UnifeiICTReport.sty:883` — `\titleformat{\chapter}[hang]{\unifeifont\color{unifeiblue}\Large\bfseries\MakeUppercase}{\thechapter}{0.5em}{}`. The counter is printed bare, with no preceding word. This is why `\appendix` alone produces a heading reading just `A`.
- `UnifeiICTReport.sty:132–137` — the `\AtBeginDocument` block pinning `\chapterautorefname` to "Seção" and the three levels below it. Document-wide, and by design: the block's own comment warns against touching one level in isolation.
- `modelo-relatorio.tex:133` — the driver already calls `\backmatter` and puts nothing after it.

## Goals / Non-Goals

**Goals:**

- Supply the mandatory approval sheet in a form that serves all four work types this template targets.
- Supply appendices and annexes that satisfy §4.2.3.3/§4.2.3.4 without breaking the numbering, cross-referencing or float machinery already in place.
- Keep both opt-in: a document that invokes neither compiles exactly as today.

**Non-Goals:**

- The ficha catalográfica (verso of the title page, §4.2.1.1.2). Required for works deposited in a library, generated by the library itself, and a separate concern.
- Errata, dedicatória, agradecimentos, epígrafe (§4.2.1.2, §4.2.1.4–§4.2.1.6). All optional, all simpler, none blocked by this change.
- Índice (§4.2.3.5, NBR 6034).
- Institution-specific approval layouts beyond the four types named. The command should be extensible, but this change ships four.

## Decisions

**One command with a type parameter, not one command per type.**
The user's call, and the right one for the dissertation case that may or may not materialize: a new type becomes a new value plus a layout block, not a new command in the public interface. The default is the course-report type, since that is what this template is primarily for.

**The course report is a norm case, not a local deviation.**
Worth recording because an earlier reading of this had it backwards. §1 Escopo: the norm "aplica-se, no que couber, aos trabalhos acadêmicos e similares, intra e extraclasse". §4.2.1.1.1(e) names *"aprovação em disciplina"* as a valid objetivo within the natureza. So a course-report approval sheet sits inside the norm's reach. The internship report is the genuinely loose case, covered by "e similares" rather than by anything explicit — the `.sty` comment should say which is which, so nobody later "corrects" the course-report layout on the false belief that it is unregulated.

**Two published layouts already disagree; treat arrangement as free.**
The UFV guide gives an UFV-PPG model (an "Assentimento:" block signed by author and supervisor) and an ABNT model (board signatures with institutions), and annotates: *"A norma indica as informações que devem ser contidas. Porém não indica a disposição dos membros da banca, podendo ser colocados lado a lado ou um abaixo do outro."* The spec therefore constrains content and typography, and leaves arrangement open. Do not encode one institution's arrangement as if it were normative.

**A sheet with blank signature lines is the expected output, not a degraded one.**
§4.2.1.3: *"A data de aprovação e as assinaturas dos componentes da banca examinadora devem ser colocadas após a aprovação do trabalho."* The sheet is printed to be signed. So an author who has not declared board members must still get correctly-shaped blank blocks, and the implementation must not warn or error about missing signatories.

**Appendices need their own structural state; `\backmatter` cannot be it.**
The conflict is direct: `\backmatter` sets `\@mainmatterfalse`, which makes `\chapter` unnumbered, but §4.2.3.3 requires the letter. Meanwhile §5.3 requires pagination to continue, which `\backmatter` does not disturb. Options considered:

| Approach | Assessment |
|---|---|
| Use `book`'s `\appendix` as-is | Gives the letter counter, but the heading prints bare `A` under this template's `\titleformat`, and there is no second sequence for annexes |
| Redefine `\backmatter` to keep numbering on | Fixes the letter, but `\backmatter` is a general-purpose hook; overloading it to mean "appendices start here" is misleading for anyone adding a glossary or index |
| Dedicated commands opening each group, with their own heading style and counter | More surface, but each group gets an independent letter sequence, its own `autoref` name, and its own centered heading — all three things the norm asks for |

The third is the direction, with the caveat that it must be verified against `\@mainmattertrue`/`false` state rather than assumed: the interaction between whatever the driver calls and the chapter counter is exactly the kind of thing that fails silently. Whether `\backmatter` also needs redefining falls out of that verification.

**Letter doubling past Z is required by the norm and will not be exercised by any real report.**
§4.2.3.3 mandates `AA` after `Z`. No report from this template will have twenty-seven appendices. Implement it anyway if it is cheap — `\Alph` overflows with an error rather than degrading, so ignoring it means a hard failure in the one case the norm explicitly names. If it is not cheap, a clear error message naming the limit is an acceptable ceiling; a silent overflow is not.

**The `autoref` name must switch by region, not be set once.**
The existing cascade block is `\AtBeginDocument` and document-wide. Appendices need `\chapterautorefname` to become "Apêndice" and annexes "Anexo", while the main body keeps "Seção" — and a reference written in the main body to an appendix must still resolve correctly. Since hyperref resolves the name at reference-expansion time, not at label time, a naive global switch would retroactively rename main-body references appearing after the switch point. This needs testing before the approach is fixed; it is the highest-risk unknown in this change.

**Sumário entries are collective, matching the published model.**
The UFV sumário model lists `APÊNDICES` and `ANEXOS` as single entries rather than one line per letter. Follow that; per-appendix entries can be revisited if the ICT asks.

## Risks / Trade-offs

- **The `autoref` name switch may not be regional.** → Highest risk here, and the one to spike first: write a two-appendix document with references from the main body into an appendix and from an appendix into the main body, and check all four combinations before committing to a design. Compile and read the PDF; do not reason about it from the hyperref source.
- **Interaction with the continuous float counters.** → `\counterwithout{figure}{chapter}` (line ~275) already detaches figure, table and equation numbering from the chapter counter, so a figure in an appendix should simply continue the sequence. That is the desired behavior per the spec, but it is an assumption to verify, since `\appendix`-like states are exactly where counter surprises live.
- **Approval sheet metadata will grow.** → Board members with three attributes each do not fit the flat `\supervisor{...}` pattern the template uses today. Whatever structure is chosen (a repeated declaration command, a list) will be the public interface authors write against, so it is worth getting right the first time rather than shipping something that has to break later.
- **The change is large for one unit.** → Accepted; the two halves were grouped deliberately because both hinge on the same structural machinery. If the appendix half turns out to need the `\backmatter` redefinition and the approval half does not, they can still be applied in either order — they touch disjoint parts of the `.sty`.

## Resolved Questions

**Is there an official ICT approval-sheet layout to follow?**
No. This repository *is* the proposal for the official ICT template, so there is no institutional layout that supersedes what is designed here. Consequence for implementation: the four layouts are ours to define, constrained only by §4.2.1.3's content list and §5.2/§5.2.4's typography — which is exactly the freedom the norm itself leaves, since it prescribes the information but not its disposition. Design for what reads well and matches the cover and title page already in the template, rather than searching for a model to copy. The corollary is that these layouts will become the reference for other people, so they should be defensible against the norm clause by clause.
